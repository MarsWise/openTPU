# RTL r8: где ресурсы, где тайминг, что можно уменьшить или ускорить (17.11.2026)

Основа: `util_hier.rpt` и `timing_worst.rpt` сборки C2 `c969ca4c` (ИЗМЕРЕНО, Vivado 2024.2.2,
после трассировки) против r5 `45b1c1d3`; исходники `rtl/`. Оценки выигрыша помечены как ОЦЕНКА.
Ёмкость XC7K480T: 298 600 LUT, 597 200 FF, 955 BRAM36, 1 920 DSP.

## 2. Тайминг: худшие пути (C2, ИЗМЕРЕНО)

Почти все худшие пути — **одна-две логические ступени и 3–7 нс трассы**: дело не в логике,
а в расстоянии между блоками.

| Клок | Запас | Путь | Логика / трасса |
|---|---|---|---|
| sys (LiteDRAM) | +0,003 | `interface1_dat_w1` (данные записи CSR) → регистры CSR | 0 ступеней, 6,9 нс |
| core | +0,004 | MXU `dj_reg_rep` → `p1_x` (выбор слива) | 1 ступень, 7,3 нс |
| userclk2 (PCIe) | +0,007 | `u_split` → `u_ch0` (`x_wbuf`, LUTRAM `u_xd`) | 0–1 ступень, 3,0–3,3 нс при периоде 4 нс |
| запись DDR | +0,029 | `bitslip` PHY → OSERDES | 1 ступень, 6,9 нс |

## 3. Предложения по RTL — маленькими шагами

Каждый шаг — отдельная правка, тест на Verilator против ISA, одна сборка.

### Площадь

| # | Правка | Выигрыш (ОЦЕНКА) | Риск | Скорость моделей |
|---|---|---|---|---|
| R1 | `TRACE_DEPTH=0` в рабочей прошивке (параметр уже есть) | −2,3 тыс. LUT, −3,9 тыс. FF, **−32 BRAM36** | нет (трасса нужна только для профиля; профильная сборка отдельно) | 0 |
| R2 | VRAND: один генератор, строка за 8 тактов (Threefry — функция счётчика, числа те же) | −5 тыс. LUT, −4 тыс. FF | малый | 0 (1 число на токен) |
| R3 | Декод весов: CQ и T5 — параметры сборки (`HAS_TCQ`, `HAS_TD5`); CQ нужен только Needle, T5 пока не используется ни одной моделью на плате | −3…5 тыс. LUT (нужен синтез без них) | малый, CAPS2 уже сообщает наличие | 0 для остальных |
| R4 | Декод весов: общий, а не на каждую из 128 линий, для редких форматов (BIN, NVFP4) — декодировать на входе потока по 16 байт/такт | до −3 тыс. LUT | средний | 0 |

### Тайминг (запасы)

| # | Правка | Эффект | Риск |
|---|---|---|---|
| T1 | Регистр на данных записи CSR LiteDRAM (`interface1_dat_w`) — CSR пишет хост, задержка в такт ничего не стоит | sys +несколько сотен пс | малый (генерированный LiteDRAM: правка в `gen_core.py`) |
| T2 | MXU: ещё одна ступень на `dj → p1_x` (слив) или репликация по колонкам | core: снять худший путь | малый, тест слива на Verilator |
| T3 | `u_split → u_ch0`: регистровая ступень (register slice) на выходе для канала 0 | userclk2 +0,5–1 нс | малый, +1 такт латентности записи хоста |
| T4 | Регистры `bitslip` PHY — в pblock рядом с OSERDES (как уже сделано для первых флопов) | запись DDR +сотни пс | малый, только ограничения |

### Скорость

| # | Правка | Эффект | Как решать |
|---|---|---|---|
| P1 | Bonsai: где теряются такты (память занята на ~53 %) | потолок ~14–15 ток/с против 8,5 | сначала профиль (`tools/decode_profile.py`, нужна сборка С трассой) |
| P2 | MXU в декоде занят ~12 %: батч 2–4 строки почти бесплатен по памяти | суммарная пропускная способность | софт + проверка `run_rows` |
| P3 | Многотокенный DSTEP для Qwen3.5 (`docs/mtp.md` 7) | спекуляция дешевле | RTL потоковой машины, позже |

## 4. Порядок

1. **Сборка «чистая площадь»:** R1 + R2 + T1 + T3 + T4. Цель — −7…8 тыс. LUT, −32 BRAM36,
   запасы sys/userclk2/записи DDR, меньше плотности у PHY. Функционально ничего не меняется,
   CFG_HASH тот же, кроме бита трассы.
2. Профильная сборка (с трассой) или прогон на текущей C2 → P1.
3. R3/R4 — по синтезу MXU отдельно (out-of-context), только если нужна ещё площадь.
4. T2 — если core останется худшим после шага 1.

## 5. C3 — что вошло в сборку (17.11.2026, вечер)

По отчётам разводки a1ba144b (C2 + rtw 4, `reports/stages/routed`, ИЗМЕРЕНО): после снятия
запасов ядро +0,098 нс, clk2x→core +0,378 нс, sys +0,009 нс, запись DDR +0,196 нс; не сходится
один путь userclk2 внутри XDMA (−0,097 нс, 10 ступеней, 69 % трассы). Перегрузка трассировки
5–6 уровня (105–108 %) в зоне MXU + памяти.

| Пункт | В C3 | Как |
|---|---|---|
| rtw 4 | да | `OTPU_LITEDRAM_RTW=4` (litedram_rtw.tcl) |
| Трасса 4096 вместо 16384 | да | `TRACE_DEPTH=4096` (CAPS сообщает глубину, хост читает её; CFG_HASH тот же) |
| Деревья разветвления | частично | `max_fanout 128` на регистрах записи LUT адаптера TMM GSC (1 500–1 800 нагрузок). `c_rst`/`ld_busy`/запись трассы — комбинационные: репликация без регистра не работает, регистр меняет такты — отложено |
| T1 / T4 (sys, запись DDR) | заменены запасами | `OTPU_SYS_MARGIN=0.10`, `OTPU_WR_MARGIN=0.05` на время P&R (сняты для битстрима) |
| T3 (`u_split → u_ch0`) | нет | на a1ba144b этот путь не худший; провалился путь внутри XDMA → `OTPU_UC2_MARGIN=0.10` |
| VRAND один генератор | нет | 8 генераторов работают параллельно по линиям, один дал бы RAND за 8 тактов: нужна остановка VPU и новая модель тактов в ISA — отдельная работа |

Проверка: Icarus — адаптер TMM GSC/CQ (14 тестов), Verilator 5.046 — вся конструкция:
`test_mm_block_offset_uses_all_eight_bits`, `test_tmm_cq.py::test_lutset_between_cq_tmms_rtl`
(RTL == ISA); margins.tcl — tclsh; `test_r8_build_plan_windows`, `test_target`,
`test_litedram_rtw` — 33 passed, 5 skipped.

## 6. C4 — площадь: неиспользуемые форматы весов MXU (17.11.2026, ночь)

**Находка (ИСХОДНИКИ).** Флаги сборки `TBIN`, `TCQ`, `TD5` и остальные из CAPS2 до сих пор доходили
только до `otpu_ctrl` (биты CAPS2): тракт данных строился со всеми форматами всегда. Выключение
флага не освобождало ни одного LUT.

**Правка.** `otpu_mxu` получил параметры `HAS_BIN`, `HAS_CQ`, `HAS_T5` (по умолчанию 1); их
проводят `otpu_slice` / `otpu_top` / `tb_top` (`HAS_TBIN`, `HAS_TCQ`, `HAS_TD5`), а `otpu_board`
подаёт туда флаги платы `TBIN` / `TCQ` / `TD5`. Декод команды и каждое использование после FIFO
(`c_binary`, `c_cq`, `c_cq4`, `c_t5`, регистры `wp_*` / `m0p.*`) умножены на параметр, D LUT-RAM
кодовой книги CQ строятся только при `HAS_CQ`. Синтез убирает таблицы тритов T5 (D штук) и декод
BIN. Хост и раньше отказывал таким программам по CAPS2 (`Board.load_program`).

**Сборка.** `OTPU_DROP_FEATURES` (build_r5_timing.ps1) обнуляет `OTPU_<f>_GEN`; CFG_HASH
считается из того, что собирается. `r8_build_c4.cmd`: C3 (rtw 4, трасса 4096, запасы) без
`TD5 TBIN TBGSC`, ожидаемый CFG_HASH **37f51889** (`r8_build_c4.cmd plan` печатает его без
Vivado). TCQ остаётся: на нём 6-битный KV-кэш (kv6 / k6v6: QST6 + TMM CQ2 GRQ), Needle CQ4, веса
Cactus CQ. `r8_card_check.py`, `r8_card_tests.sh`, `r8_restore_pcie.cmd` принимают C4.

**Выигрыш — ОЦЕНКА, не измерено:** декод весов MXU вырос с r5 на +8,6 тыс. LUT (раздел 1), из них
T5 и BIN — часть; точную цифру даст отчёт C4 (`util_hier.rpt`, узел `g_wsk` / `u_mxu`).
Yosys здесь без плагина slang, поэтому SV-дизайн им не синтезируется.

**Проверка (RTL SIMULATED, Verilator 5.046):** `tests/test_mxu_format_gates.py` — MM int8 / int4 /
fp4 PAIR / NVFP4 PAIR и TMM GSC / GRQ / GRQ QUAD на m8 без BIN / CQ / T5 (и без одного CQ) ==
ISA, с AXI-задержками; по умолчанию (всё включено) `test_tmm_t5`, `test_tmm_cq`, `test_tmm_grq`,
адаптер CQ / GSC — 47 passed; BIN, BIN GSC, QST6 + проверки — 56 passed; хэши C3 / C4, разбор CAPS2 в `r8_card_check`.

Дальше по площади (не в C4): VRAND один генератор (−5,7 тыс. LUT, нужна остановка VPU),
LDX и TFN atan — тоже только биты CAPS2 (тракт строится всегда; моделей на карте нет), трасса 0.

**Результат сборки C4 (508da1c6, 18.11.2026, Vivado 2024.2.2, после трассировки):** LUT 209 213 → **199 715
(−9 498)**, из них MXU 57 982 → 48 509 (−9 473: собственная логика −1 961, остальное — декод весов,
разнесённый по позициям массива); FF −539; BRAM и DSP без изменений; слайсы 88,76 % → 85,47 %.
WNS +0,059, WHS +0,031 (запасы те же). sha256 3492CA48…4331, CFG_HASH 37f51889. На карте ещё не
проверялась.

## 7. r8 против r5: два опыта на DDR3 (18.11.2026)

r5 45b1c1d3 на той же карте чист (0/0, включая run_rows), r8 (2c800a8f, C3, C4) — нет. Разница r5 → r8
на пути к памяти: регистр на данных записи в `otpu_mem_ch` (bf422b88, ради −1,20 нс) и размещение
(VPU рядом с PHY канала 0, `u_ch0` ушёл от своего PHY). RTL адаптера DRAM и LiteDRAM — те же.

- **Симуляция** (`tools/memch_test.py wreg`): `otpu_mem_ch` с регистром и без него — 60 из 60 PASS
  на 10 сценариях (чтение после записи, частичные и общие слова, задержки контроллера, такты Gen2)
  с моделью и с собственным контроллером LiteDRAM. Логически регистр равносилен пути r5.
- **Опыт A** (`r8_build_a.cmd`, каталог `…-<rev>-a`): RTL r8 без BIN / BIN GSC, путь записи r5
  (`OTPU_MEMCH_WREG=0`), rtw 3, трасса 16384. CFG_HASH 432e34c2.
- **Опыт B** (`r8_build_b.cmd`, каталог `…-<rev>-b`): C4 с MXU на DSP X1..X8 / RAM X1..X8 + X0 и
  DSP X0 закрытой для остального (`OTPU_DSP_PROHIBIT_COLS=0`): VPU / QUANT уходят к X9..X11, от
  PHY. CFG_HASH 37f51889.
- Хост: проверка BIN больше не путает T5 с BIN (T5 несёт бит BIN; у T5 своя проверка TD5).
