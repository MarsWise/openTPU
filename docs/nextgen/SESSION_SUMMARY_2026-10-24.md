## 1. Цель и ТЗ

- Проект: **openTPU NextGen**, FPGA-ускоритель ИИ «hardware first». Основа —
  `FeSens/openTPU` (автор), форк `MarsWise/openTPU`, ветка
  `feature/nextgen-hardware-first-vla-bitnet-vllm`, Draft PR #1.
- Полное ТЗ лежит в описании проекта на claude.ai (Master Autonomous Engineering Prompt).
  Коротко: LLM, BitNet/тернарные модели, CNN/YOLO, VLM, VLA, MoE/MTP, родной vLLM,
  `--strict-fpga`. Любое изменение проверяется, классы доказательств не смешиваются, данные не
  выдумываются.
- Пожелания пользователя (Костя) за сессию:
  - **r5**: максимум аппаратного ускорения в одной прошивке (VLA, VLM, диффузия, видео и аудио,
    YOLO), собрать сразу всё, не по частям. Две сборки: m8 @ 150 МГц (рецепт автора + наше)
    и m4 @ 133 МГц (запасная). Скрипты Vivado пользователь запускает сам.
  - **r6**: всё на плате, **на хосте никаких вычислений** (план `R6_PLAN.md`).
  - Отвечать по-русски. Параллельно с Claude в проекте работает Codex.

**Как гонять что-то на карте:**
- `_claude\claude_run.cmd` загружает на хост `sync.bundle` и `claude_run.sh` и запускает
  `claude_run.sh` в фоне. Скрипт сам подтягивает код из бандла (fast-forward), держит
  `flock` (повторный запуск не начнёт второй прогон) и в конце пакует `/tmp/claude_run.tgz`.
  Результат возвращается в `_claude\claude_run.log` и `claude_run.tgz` (`claude_fetch.cmd`).
- `run_status.cmd` — статус прогона; `card_info.cmd` — регистры карты (build, CAPS, хэш).
- Прогон на карте всегда готовится как новый `claude_run_<имя>.sh`, копируется в
  `claude_run.sh`, а предыдущий сохраняется как `*.used`.
- Прошивка по JTAG (`*_1_jtag.cmd`) и PCIe rescan (`*_2_pcie.cmd`, sudo) — **только
  пользователь и только после его явного «да»**. Загрузка энергозависимая, `.mcs` во флеш не
  пишем.

**Особенности моста, которые уже стоили времени:**
- `.git` рабочего дерева указывает на Windows-путь. В `device_bash` git вызывать с
  `GIT_DIR=$M/openTPU/.git/worktrees/pasted-text-processing GIT_WORK_TREE=$M/openTPU.worktrees/pasted-text-processing`
  и `-c safe.directory='*'`.
- Удалять в подключённых папках нельзя (нужно разрешение), поэтому git оставляет `.lock`-файлы.
  Бандл делать так: `git bundle create - <ref> ^<base> > file`. **В рабочее дерево с моста не
  коммитить и не сливать**: это делает пользователь.
- `device_commit_files` однажды записал устаревший файл под тем же именем (`sync.bundle`
  оказался v16). Писать файл под новым именем (`sync_vNN.bundle`), проверять размер и
  `strings | head`, а потом делать `cp` на устройстве.
- Контейнеру не хватает памяти: тестовые файлы гонять по одному; самые большие сборки
  Verilator (S=2, m8) — в один поток. Плагин `tools/nextgen/pytest_container_plugin.py`
  делает именно это и снижает порог свободного диска для кэшей (по умолчанию 20 ГБ).
  Фоновая задача ограничена 2 часами.

1. Сборка r5-m8: тайминг на 150 МГц не подтверждён. При ≥ 0 — загрузка и проверка, при < 0 —
   r5-m4 или донастройка по отчётам этапов.
2. Правки Codex в контейнере перепроверены частично: TFN/SE/MAC/torchdev 86 прошли. Не
   перепроверены: `test_quant_rtl`, `test_rtl` (TMM/QUAD m8), `test_r5_board`, `test_vops`,
   `test_waits`, `test_ternary`, `test_conv`, `test_cnngraph`, `test_host`, `test_loadcal`.
   По словам Codex, они проходят.
3. SmolVLA base на карте не измерен; элементные операции VLA пока на хосте.
4. vLLM: DeviceBusy на втором движке `vllm_smoke`. Нужен планировщик нескольких моделей.
5. На хосте нет чекпойнтов Qwen3 / LFM2.5 / Qwen3.5 (qual пропущен) и нет Verilator
   (38 host-тестов падают только из-за этого).
6. MiniCPM-V с картинкой на карте не проверялся.
7. Публикация: в форке ветка всё ещё `668dcff5`, около 138 коммитов не запушено (у сессии
   Claude нет прав на push; пушит пользователь).
8. Документы `OPERATOR_COVERAGE_MATRIX.md` и `MODEL_COMPATIBILITY.md` устарели (BitNet там
   указан гибридным, есть отметки «не выбран чекпойнт»). Обновить по §5.

## 8. Уроки (обязательны к соблюдению)

1. **Verilator не заменяет синтез.** Защёлки и разворачивание памяти в триггеры тесты не
   видят. Каждый изменённый RTL-модуль перед полной сборкой синтезировать в Vivado отдельно
   (out-of-context) и проверить защёлки, `no_clock` и отображение памяти в RAM.
2. **IMEM на карте — 4096 инструкций.** Длинная программа раньше загружалась молча и
   исполнялась испорченной (YOLOX `--wsplit` mAP 0, SmolVLA base 0,878). Теперь загрузчик
   отказывает. Компилятор обязан укладываться: цепочки HALT CHAIN, разбиение по строкам,
   построчный цикл свёртки.
3. **`loadcal`** начинает с калибровки процессора ядра, если тот не остановлен. После
   `memcal cal --force` процессор остановлен, и база — калибровка хоста. После перезагрузки
   прошивки: `memcal selfcal`, затем `loadcal` (`OTPU_LOAD_CENTER=1` на 133 МГц; на 150 МГц
   включается сам).
4. Монитор, который только читает регистры, открывает транспорт с `dma=False`, иначе он
   занимает блокировку устройства.
5. Прежде чем винить память, проверить данные: в 4c/4d `--wsplit` mAP 0 давала не DDR3, а IMEM.
6. Время вызовов, а не счёт, — главный тормоз. Веса держать резидентно, проход модели одной
   цепочкой программ (как BitNet и YOLOX).
